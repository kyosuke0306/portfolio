# ポートフォリオサイト

Vanilla HTML / CSS / JS の静的サイト。ビルド不要。

- **公開（閲覧用）**: https://kyosuke0306.github.io/portfolio/
- **編集用**: `edit.html` — ローカル専用。公開サイトには含まれない（`_config.yml` で除外）。
- **予定スケジュール**: https://kyosuke0306.github.io/portfolio/schedule.html — 自分用の予定管理。ポートフォリオ本体からはリンクしていない。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `data.json` | **ポートフォリオの表示内容の唯一の情報源。** 閲覧ページも編集ページもこれを読み込む。 |
| `index.html` | 閲覧専用ページ。編集ボタン・編集モーダルなし。GitHub Pages で公開される。 |
| `edit.html` | 編集用ページ。編集モーダルと「公開する」ボタンを持つ。ローカルでのみ開く。 |
| `app.js` | 上記2ページ共通。編集UIが無ければ描画だけして終了する（`editorOverlay` の有無で判定）。 |
| `schedule.html` | 予定スケジュールのページ。`data.json` も `app.js` も使わない独立したページ。 |
| `schedule.js` | 予定ページ専用。予定の追加・編集・カレンダー描画。 |
| `style.css` | 全ページ共通。 |
| `_config.yml` | GitHub Pages（Jekyll）のビルド設定。`edit.html` と `README.md` を公開対象から除外。 |

## データの流れ

```
編集ページで入力 → localStorage（下書き） → 「公開する」→ GitHub に data.json をコミット
                                                              ↓
                                            GitHub Pages が再ビルド（1〜2分）
                                                              ↓
                                                  閲覧サイトに反映
```

- 閲覧ページは `data.json` だけを見る。localStorage は一切参照しないので、
  自分のブラウザに古い下書きが残っていても公開内容が正しく表示される。
- 編集ページは下書きがあればそれを優先し、無ければ公開済みの `data.json` から始める。

## 初回セットアップ（GitHub トークン）

「公開する」ボタンを使うには、GitHub のアクセストークンが一度だけ必要。

1. https://github.com/settings/personal-access-tokens/new を開く
2. **Repository access** で `kyosuke0306/portfolio` だけを選ぶ
3. **Permissions → Repository permissions → Contents** を `Read and write` にする（他は不要）
4. 有効期限を設定してトークンを発行し、文字列をコピーする
5. 編集ページの「GitHub アクセストークンを設定」を開いて貼り付け、「トークンを保存」

トークンはこのブラウザの localStorage にのみ保存され、送信先は GitHub API だけ。
`edit.html` は公開サイトに含まれないので、トークンが外部に出ることはない。
期限が切れたら同じ手順で発行し直す。

## 内容を更新する手順

1. ローカルサーバーを起動する

   ```bash
   npx --yes serve -l 5500 .
   ```

2. http://localhost:5500/edit.html を開き、「編集」から内容を入力する
3. 「公開する」を押す
4. 1〜2分後に https://kyosuke0306.github.io/portfolio/ へ反映される

`git pull` すると、公開した `data.json` が手元にも反映される。

「JSONを書き出し / 読み込み」はバックアップや別マシンへの移行用に残してある。

## 下書きと公開内容がずれたとき

編集ページの下書き（localStorage）は、公開内容とは独立して残る。
別の端末やブラウザで公開した変更は、こちらの下書きには入ってこない。
そのまま「公開する」を押すと**その変更が巻き戻る**。

このため、下書きが公開中の内容と異なるときは編集パネルに警告が出る。
心当たりがあるときは「下書きを破棄」を押して、公開中の内容から編集し直す。

## 予定スケジュールのページ

`schedule.html` は自分用の予定管理ツール。ポートフォリオの内容とは無関係で、
`data.json` にも書き込まない。編集ページのヘッダー「予定」からも開ける。

| | |
| --- | --- |
| 保存先 | その端末のブラウザの `localStorage`（キー: `portfolio.schedule.v1`） |
| 公開 | ページ自体は GitHub Pages で配信されるが、**予定の中身はブラウザから出ない** |
| 検索エンジン | `noindex` 指定で載らない。ポートフォリオ本体からもリンクしていない |

- 月カレンダーで日を選び、その日の予定を追加・編集する。時刻を空欄にすると終日の予定になる。
- 分類は 仕事 / 学習 / 私用 / その他 の4つ。カレンダーのマスには分類の色の点が出る。
- 一覧は「選んだ日 / 今日以降 / すべて」で切り替えられ、キーワードと完了状態で絞り込める。
- 編集欄は入力するたびに保存される（保存ボタンは無い）。

> **予定は端末ごとに独立している。** 別の端末やブラウザには自動では出てこない。
> 移すときは「JSONを書き出し」→ 移し先で「JSONを読み込み」。読み込みは置き換えではなく
> **同じ id のものを上書きし、無いものを足す**ので、両方に入れた予定が消えることはない。

> 保存先はポートフォリオの下書き（`portfolio.data.v1`）とは別のキーなので、
> 編集ページの「下書きを破棄」で予定が消えることはない。

## 注意

- `index.html` の静的な初期表示（名前・自己紹介・`<title>`）は JS 実行前の一瞬と
  検索エンジン向けのもの。名前や肩書きを変えたときは、ここも手で直して push する
  （`schedule.html` のフッターの名前も同じく手で直す）。
- 画像（アバター・サムネイル）は base64 で `data.json` に埋め込まれる。
  アップロード時に自動で縮小される（アバター 512px / サムネイル 1000px / JPEG 品質 0.82）ので、
  スマホの写真をそのまま入れても数十〜数百KBに収まる。
- ブラウザの保存容量を超えると下書きが保存できない。その場合は編集パネルにエラーが出る
  （黙って失敗すると、古い下書きを公開して内容を失うため）。
- `file://` で直接開くと `data.json` の fetch が CORS で失敗する。必ずローカルサーバー経由で開く。
